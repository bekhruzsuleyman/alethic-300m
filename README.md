# Alethic-300M

A from-scratch 300M-parameter language model project: a matched pair of
decoder-only models (SGCA, Sin-Gated Control Attention, and a GQA baseline)
trained on a code-first corpus (10% Uzbek), plus a small agent harness that
lets the fine-tuned model read, edit and run files and search Wikipedia.

Weights and tokenizer: https://huggingface.co/bekhruzsuleyman/alethic-300m (SFT-3c is in `sft/sft3c/`)

Just want the agent? The harness alone, without the training code, is in its own small repo:
https://github.com/bekhruzsuleyman/alethic-agent

## Layout

| Folder | What is in it |
| --- | --- |
| `src/alethic/model` | SGCA and GQA attention, transformer |
| `src/alethic/train`, `data`, `tokenizer`, `eval` | training loop, data pipeline, tokenizer, evaluation |
| `src/alethic/sft` | supervised fine-tuning (tool-use traces) |
| `src/alethic/agent` | the agent harness: read, write, edit, shell, search |
| `tools/` | generators for the fine-tuning data (math, skills, search, programs, terminal, errors, identity) |
| `tests/` | unit tests |
| `configs/` | training configs |
| `deploy/` | Windows double-click launchers and Modal apps |

## Results: SFT-3c vs SFT-3b

50 fixed prompts, kept out of the training data. 35 are graded by a checker; the other 15 are open-ended and
were read by hand (`reports/eval_answers.txt`). Passed / graded:

| Group | SFT-3b (temp 0) | SFT-3c (temp 0) | SFT-3c (temp 0.3) |
| --- | --- | --- | --- |
| identity | 6/6 | 6/6 | 5/6 |
| short answers | 2/7 | 5/7 | 4/7 |
| Uzbek | 1/2 | 1/2 | 0/2 |
| knowledge | 0/1 | 1/1 | 1/1 |
| honesty | 2/3 | 0/3 | 1/3 |
| write a file | 0/4 | 2/4 | 2/4 |
| fix a bug | 1/4 | 2/4 | 2/4 |
| edit at a line | 0/3 | 0/3 | 0/3 |
| refuse | 3/4 | 1/4 | 2/4 |
| **total** | **16/35** | **19/35** | **18/35** |

SFT-3c is 3 prompts better than SFT-3b. That is a small sample, so treat it as a direction, not a proof.
Still weak: line-number edits (0/3 for every model) and honesty. Temperature 0 versus 0.3 differs by one prompt.

## The SFT dataset: alethic-newborn

All fine-tuning data is generated by the scripts in `tools/` and is packed
into numbered shards:

    alethic-newborn0001.jsonl   alethic-newborn0001.parquet
    alethic-newborn0002.jsonl   alethic-newborn0002.parquet
    alethic-newborn0003.jsonl   ...

Every shard mixes all kinds of examples (math through python, read-map-edit,
search, programs, terminal tasks, error fixing, identity). Each record is
`{"id", "kind", "lang", "segments": [{"t": text, "loss": 0 or 1}]}`; only
segments with `loss` 1 are trained on. `tools/release/pack_newborn.py` builds
the shards, and `alethic-newborn.manifest.json` lists the count per shard and
per kind. The shards are on Hugging Face (accept the terms to download):
https://huggingface.co/datasets/bekhruzsuleyman/alethic-newborn
